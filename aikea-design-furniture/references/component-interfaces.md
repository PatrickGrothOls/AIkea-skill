# Optional component configurators

These components emit or apply the same shared construction inputs as authored
parts. Use their actual interfaces and selected product evidence. A recipe's
limits do not constrain furniture that can be built with other supported tools.

| Component | Required host/inputs | Owned effects and evidence |
| --- | --- | --- |
| Tall-storage cabinet | Completed measured project and supported allocated boundary; [unit taxonomy](../../aikea-build-units/references/unit-taxonomy.md) | Editable panel/joint/grid recipe, generated-file conflict protection and common build. Read the actual footprint/material/door rules before adapting. |
| Structural base | Explicit footprint and configured support dimensions; [base recipe](../../aikea-build-units/references/base-recipe.md) | Deck/rail/brace recipe, paired cuts and supported segmentation. Geometric connection spacing does not establish deck/load approval. |
| Wooden drawers and runners | Named real side/support panels, opening and available travel; [drawer host](../../aikea-build-drawers/references/drawer-host-interface.md) | Follow the mandatory [complete installation](../../aikea-build-drawers/references/complete-drawer-installation.md): exact runners, any required hinge-clearance spacers, child parts, host/child machining, purchases and motion proof. |
| Slab door and hinges | Real front and opposing upright inside support face; [hinge construction](../../aikea-build-doors/references/shared-hinge-construction.md) | Shared cup/plate pattern, exact hardware and closed/open states. Current interface is upright and front-facing; a side-opening design needs a suitable frame/interface. |
| Multi-part front | Selected layer materials, outline/borders and thicknesses; [applied-frame recipe](../../aikea-design-framed-doors/references/applied-frame.md) | Separate physical backing/frame plus shared pocket; attachment stays an explicit requirement. Other front constructions can use the same primitives. |
| Hinged multi-part front | Direct flat front child and real parent support; [whole-front host](../../aikea-build-doors/references/assembly-fronts.md) | Real layer drilling, parent plate holes, exact purchases and one complete-child motion. Parallel layers/full bores required; adhesive, screws/load and full sweep remain separate. |
| Adjustable Korrekt feet | Horizontal deck, sourced 61854/70151 pair placements and explicit edge margin; [mounting](../../aikea-build-units/references/korrekt-mounting.md) | Plate-foot purchases, sourced footprint and shared mounting negative. Preserve physical-fit, top access, adjustment, screw engagement and deck-load gaps. |
| Recessed linear lighting | Existing part-local run, face, selected profile and length; [lighting skill](../../aikea-add-lighting/SKILL.md) | Common groove, luminaire purchase, owned on/off review and removal. Include lighting by default; preserve an explicit user opt-out. Wiring/power, other hardware and wider motion need separate checks. |

Select components against current available space, material and manufacturing
frames; do not rename an arbitrary host to make it look compatible. When a feature
is removed, rebuild without its registration and confirm its machining/purchases
disappear while other features remain. Retained inactive source is not a second
physical instance. Review the complete parent after adding or moving components.

For an unsupported host or new product, inspect the nearest implementation and
source evidence. Extend the smallest missing interface/operation, test its real
participants independently and qualify its evidence through the existing gate.
Do not add a furniture-purpose skill or silently relax the component's checks.
